# VERIFY: sandbox checks to run by hand

The PayPal sandbox checks below were run on 2026-11-12 (see Status). The model check V6 ran through the local Claude Code account, not the hosted API. The code paths below exist and are covered by tests against a stand-in; these checks confirm them against the real sandbox. Run them only after a person approves, with sandbox credentials only.

## Setup (once)

1. Create one sandbox business account and one REST app for each seller you want live (`POWER_COMPANY`, `GARDEN_SHOP`, `MOBILITY_DIRECT`, `MAPLE_LANE`, `LAKESIDE_TICKETS`). Two or three are enough for the video; sellers without keys keep using the local stand-in.
2. Put each app's client id and secret in `.env` as `PAYEE_<SELLER>_CLIENT_ID` and `_CLIENT_SECRET`.
3. Create a sandbox personal (buyer) account for the payer.
4. Expose the server on a public HTTPS URL and set `PUBLIC_URL`. On each seller's app register a webhook to `<PUBLIC_URL>/api/webhooks/paypal/<seller key in lowercase with underscores>` with the events `CHECKOUT.ORDER.APPROVED`, `PAYMENT.AUTHORIZATION.CREATED`, `PAYMENT.AUTHORIZATION.VOIDED`, `PAYMENT.CAPTURE.COMPLETED`, `PAYMENT.CAPTURE.DENIED`, `PAYMENT.CAPTURE.REFUNDED`. Put the webhook id in `PAYEE_<SELLER>_WEBHOOK_ID`. A seller with keys but no webhook id rejects every webhook (fail closed).

## V14 (needs two sandbox apps)

PayPal itself refusing another merchant's app. Set up two sellers with different REST apps (also closes V3). Run scenario 1 for seller A, approve in PayPal, and copy the authorization id from the call trace (before pressing Stop). Then `OWNER=<seller A key> OTHER=<seller B key> AUTH_ID=<authorization id> node scripts/permissionCheck.js`. The default is a read, which cannot move money; `PERMISSION_TRY_CAPTURE=1` tries a capture and would capture if PayPal wrongly allowed it. Expect a refusal (status and issue printed, for example `PERMISSION_NOT_GRANTED`). If PayPal answers differently, write the actual issue code in the README line that mentions `PERMISSION_NOT_GRANTED`.

## Fallback if V1 or V2 fails (order-only path)

Create the order with intent `CAPTURE`, leave it `APPROVED` after the payer approves, capture it when the family approves, and discard it when the family stops. The hold is then an approved order rather than an authorization, so the screen texts change: "Approved by Mom, not charged yet" and "Payment cancelled before charge". The valid time of an approved order is not confirmed, so shorten the hold window and drop the "voided" scene from the video. This path is not implemented in code; implementing it means replacing the gateway methods in `server/paypal/sdkLive.js` (or `server/paypal/live.js` with `PAYPAL_TRANSPORT=rest`).
